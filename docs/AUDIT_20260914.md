# Audit and statistics — 2026-09-14

Follow-up: [manual annotation/source review](MANUAL_DATA_REVIEW_20260914.md)
compares the rig's actual labeled frames with the local training export and
identifies different annotation versions and unimported frames. The checks below
cover the local datasets; they are not proof that every manually labeled source
frame reached every historical checkpoint.

The code is better guarded, but the available evidence does not support a claim
of reliable field detection yet. On 704 newer diagnostic images, the default
`boat_v4_s_best` detects 88 of 168 labeled boats and produces 41 unmatched
predictions at confidence 0.45 / IoU 0.5. That is 68.2% precision, 52.4% recall
and F1 0.593. No checkpoint or live camera configuration was promoted or retrained.

## Evidence and measurements

- Six checkpoints, each run on the same 831 validation and 815 test-directory
  images: **9,876 evaluated image/checkpoint pairs**. CPU FP32, four threads,
  imgsz 960, input at saved annotation resolution. Full predictions, checkpoint
  and dataset hashes, per-recording metrics, and timings are retained.
- **11,237 local dataset images** audited, including full image decoding,
  normalized box validation, file and decoded-pixel hashes across splits,
  reserved-test membership and normalized capture-session identifiers.
  No structural, exact-duplicate or same-timestamp session issues were found.
- **38 historical metric rows** recomputed from saved predictions; all reported
  fields match exactly. This verifies arithmetic, not ground-truth correctness.
- Two powered-on rigs inspected over SSH and existing read-only status APIs.
  **15,691 raw frame files** inventoried by size and timestamp. No frame-size
  mismatch against the available manifests. This is not decoding every remote
  pixel or validating every archive label.
- One current preview image from each rig decoded locally and passed through all
  six checkpoints. Both images are color and show a dim indoor wall/rig parts;
  all twelve predictions had zero detections at confidence >=0.45. Two frames
  without a reviewed target do not establish precision or recall.

The validation leader is not the newer-set leader. The small difference between
the default and v3-unfrozen on the newer set is not a demonstrated statistical
advantage across independent operating conditions. All positive dataset images
have one annotation box; secondary targets and inconsistent historical box
conventions still need review. Adjacent frames are strongly correlated.

Checkpoint names are also insufficient provenance: `boat_v4s_frozen_color_best`
contains `freeze=None`, despite its name. All six checkpoints declare class 0
as `boat`. The three older hashes documented in EVALUATION.md match their current
files. Detailed training arguments are in `checkpoints.json`.

## Fixes made in this audit

| Area | Finding | Change and verification |
| --- | --- | --- |
| Tiled detection | Per-tile predictions could create duplicate detections/track IDs in overlaps. | Global confidence-ordered NMS in working coordinates; duplicate/nearby-target regression. |
| Model classes | Runtime treated every detected class as a boat. | Resolve boat/ship/vessel IDs from checkpoint names, filter predictions, reject incompatible marker weights. |
| Range while coasting | A missed target could remeasure background at its predicted box or reuse its old waterline; the old detection timestamp rewound the metric filter. | Only current visual observations update visual range. Current tag poses can update at the current timestamp. Expose measurement age and missed frames; predicted range is not logged as a fresh raw measurement. |
| Fusion configuration | A high detector threshold was rejected even with no segmentation runner. | Apply the unknown-obstacle threshold compatibility check only when that branch exists. |
| ROI measurement | Horizon smoothing crossed recording boundaries; roll used the wrong aspect ratio; center coverage overstated the crop's achievable IoU. | Reset between recordings, measure pixel slope, compute retained-area IoU ceiling. |
| Segmentation geometry | Resizing padded network masks shifted hull/waterline coordinates. | Request native `retina_masks` before mapping masks to the working frame. No segmentation accuracy claim without real weights. |
| Camera trial statistics | The water-band bottom argument was ignored; promised review overlays were absent. | Respect both band bounds, save optional sampled overlays, record source FPS/resolution, p50/p95 timing and measured sampling throughput. |
| Dataset audit | Empty/corrupt datasets and some simultaneous-camera session aliases could pass. | Decode verification, pixel hashes and normalized session identities; reserved test checks. |
| Dataset repair | NaN could become a plausible box after clipping; nonnumeric rows crashed; moves could overwrite existing pairs. | Quarantine unusable labels, check both destinations before moving, guard missing datasets/mounts. Actual datasets were not repaired again. |
| Annotation plan | The saved labeling plan could reintroduce the known duplicate recording and split-camera leakage. | Remove duplicate alias from validation and keep the simultaneous camera in train. |
| Raw input | Rig 1's three-channel BGR frames use a legacy `.gray` suffix and were invisible to the local reader. | Read `.bgr` and `.gray`, take shape/channel semantics from the manifest, validate size and pixel format. True luma inputs remain recognizable as monochrome. |
| Raw frame order | Reused frame counters interleaved two capture segments in filename order. | Replay in embedded timestamp order. Reproduced on two archived sessions; regression covers restarted counters. |

Global NMS has a measurable tradeoff. Reprocessing saved `full_tiles` predictions
at the same IoU=0.7 merge threshold reduced FP **515 -> 237**, but TP also fell
**365 -> 357** (FN 325 -> 333). In `band_tiles`, FP fell 218 -> 170 and TP 353 ->
351. This isolates duplicate suppression on existing outputs; it is not a new
independent detector evaluation or a reason to enable tiling by default.

Filename sorting creates one time reversal in rig 0 session `20260911-141624`
and 84 reversals in rig 1 session `20260911-142550`, because a frame counter
restarted. Sorting by embedded timestamps resolves those reversals; there are
no duplicate timestamps in the inventoried sequences. Saved label/frame-index
alignment must be rechecked before reusing annotations of affected sessions.

The second rig's last manifest note says luma but its structured fields and
file size specify 4608x2592x3 BGR (35,831,808 bytes/frame). Reader decisions now
use those explicit fields instead of the suffix or free-text note.

The corrected reader was also checked against an actual downloaded `.gray`
frame from rig 1: it decodes as 2592x4608x3 with the original BGR channels.
The updated camera-trial command completed an eight-frame real-video smoke test
and produced its JSON statistics and review overlay.
