# Проверка разметки кадров

Запуск из корня проекта:

```sh
venv/bin/python viewer/server.py
```

Откройте <http://127.0.0.1:8001/dataset_review.html>. Риг для работы не нужен:
интерфейс использует уже скопированные 5 016 кадров. Он доступен только на этом
компьютере. Ссылка также есть в основном просмотрщике.

## С чего начать

1. **Некорректные рамки — 108 кадров.** Красным показана исходная рамка с рига,
   голубым — доступная локальная версия. Если локальная рамка правильно охватывает
   корабль, выберите её. Иначе нажмите «＋ Рамка» и обведите видимую часть корабля.
2. **Разные версии — 455 кадров.** Здесь собраны все расхождения с имеющимися
   локальными наборами, включая color/mono и test. Поэтому число больше прежних
   235 расхождений только с color/train. Проверьте корабль по изображению:
   автоматически предпочитать одну папку другой нельзя.
3. **Совпадения имён — 492 кадра, 246 пар.** Под основным изображением виден кадр
   с тем же именем в другой части набора. Это совпадения имён, а не доказанные
   дубликаты изображения. Если знаете исходную запись, укажите её название или
   дату/время в поле «Запись». Неизвестное происхождение лучше отложить с комментарием.
4. В «Все кадры» можно проверить остальные изображения. Очереди пересекаются:
   один кадр может содержать несколько проблем. Фильтр статуса показывает
   непроверенные, отложенные, подтверждённые и исключённые кадры.

## Редактирование и решения

### Перепроверка «корабля нет» по YOLO

В отдельном терминале из корня проекта запустите:

```sh
venv/bin/python review_background.py
```

Скрипт берёт только текущие сохранённые решения «Подтверждён» с пустыми рамками
и явным подтверждением фона. Запускает `weights/boat_v4_s_best.pt` на исходных
изображениях, размер входа 960, порог уверенности 0.15, CPU. Это новый проход
модели, а не восстановление старых срабатываний; исходные версии разметки не
считаются предсказаниями. Можно указать другую модель и порог:

```sh
venv/bin/python review_background.py --weights weights/boat_v5_s_best.pt --conf 0.25
```

Перезапустите сервер, если он был запущен до обновления кода, и откройте
<http://127.0.0.1:8001/dataset_review.html?queue=yolo_background>.
В очереди «Корабля нет, YOLO нашёл» первыми идут кадры с большей уверенностью.
Жёлтые рамки и проценты показывают предложения модели; их можно скрыть отдельно.
Если корабль есть, нарисуйте правильную рамку и сохраните. Если это ложное
срабатывание, подтвердите фон ещё раз. После сохранения (также при откладывании
или исключении) кадр исчезнет из этой очереди; история решения сохраняется.
Повторный запуск скрипта снова проверяет все текущие подтверждённые фоны,
включая уже пересмотренные.

Отчёт сохраняется в `results/manual_training_review_20260914/review/yolo_background.json`
каждые 25 кадров и в конце. Обновите страницу, чтобы увидеть новые результаты.
Неполный проход явно отмечен; отсутствие срабатывания не доказывает отсутствие
корабля. Для короткой проверки можно использовать `--limit 10 --out /tmp/yolo-smoke.json`,
не заменяя отчёт редактора. Скрипт печатает найденные ID в терминал и сохраняет
рамки, уверенности, версию решения, хеши исходников, модель и параметры в JSON.
Исходные метки и решения не изменяются автоматически.

- Зелёные рамки — ваше текущее решение. Обведите **каждый видимый корабль**.
  Берег, небо и вода не получают рамок класса boat. Маски фона этот редактор не создаёт.
- `D` (или `В` в русской раскладке) — нарисовать новую рамку. Перетаскивайте рамку
  целиком или за любой из четырёх углов. Минимальный размер новой рамки — 2 пикселя.
- «Удалить» удаляет выбранную рамку; «Отменить» возвращает предыдущее изменение рамок.
- `N` (или `Т`) / «Корабля нет» — явно подтвердить пустой кадр. Пустая исходная
  метка сама по себе не считается подтверждением отсутствия корабля.
- «Подтвердить и дальше» сохраняет решение и переходит к следующему кадру.
  `Enter` делает то же, когда фокус не находится в поле ввода или другой кнопке.
- «Отложить» сохраняет текущие рамки и комментарий для повторной проверки.
  «Исключить» отмечает кадр непригодным. Оба решения можно пересмотреть через фильтр статуса.
- Стрелки влево/вправо переключают кадры. Несохранённые изменения вызывают запрос
  перед переходом. При конфликте двух вкладок обновите кадр: чужое сохранение
  не перезаписывается молча.
- «Обновить» загружает последнее сохранённое решение. История показывает предыдущие
  решения; все версии остаются в базе и экспорте.

## Где хранятся результаты

Исходный снимок `results/manual_training_review_20260914/source_dataset/` и локальные
обучающие наборы не изменяются. Решения и история хранятся в
`results/manual_training_review_20260914/review/decisions.sqlite3`.
Для переноса прогресса сохраните эту базу вместе с исходным снимком и файлами аудита.

«Скачать решения» создаёт ZIP: одобренные метки YOLO в `labels/<исходная часть>/`,
`manifest.json` с решениями, контрольными суммами и причинами задержки импорта,
а также `history.json` со всеми версиями решений. Исключённые и отложенные кадры
есть в манифесте, но не получают обучающих меток в архиве. Пустой файл метки означает
подтверждённый фон. Изображения в ZIP не дублируются.

**Подтверждение рамки не утверждает разбиение train/val/test.** Уточнение записи
сохраняется как ручное свидетельство; оно не переносит кадры между частями набора.
Перед обучением нужно отдельно согласовать записи и отложенные проверочные сессии.
Поэтому экспорт помечен `training_ready: false` и не содержит `dataset.yaml`.

Сервер сверяет SHA-256 исходного изображения и метки перед просмотром, сохранением
и экспортом. Если файл изменился после аудита, операция блокируется до повторной
сверки. Изменённую локальную альтернативу также нельзя выбрать как прежнюю версию.
